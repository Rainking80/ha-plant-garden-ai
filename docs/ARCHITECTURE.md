# Architecture

Status: **M0** (scaffolding). This document describes what exists today and is
updated with every milestone. The target picture is in
[AGENT_SYSTEM_PROMPT.md](AGENT_SYSTEM_PROMPT.md).

## Overview

```
Browser (HA frontend)                         Home Assistant core
┌─────────────────────────────┐   WebSocket   ┌──────────────────────────────────┐
│ <plant-garden-panel>  (Lit) │ ────────────▶ │ websocket_api.py  plant_garden/* │
│ frontend/src → Vite bundle  │               │                                  │
│                             │ ◀──── HTTP ── │ panel.py  static path + panel    │
└─────────────────────────────┘               │ __init__.py  setup / unload      │
                                              │ config_flow.py                   │
                                              └──────────────────────────────────┘
```

## Backend (`custom_components/plant_garden/`)

| Module | Responsibility |
|---|---|
| `__init__.py` | `async_setup`: static path + WebSocket commands (once per HA run). `async_setup_entry`: runtime data, platforms, sidebar panel. `async_unload_entry`: removes the panel. |
| `config_flow.py` | One step: garden name. `single_config_entry` in the manifest limits it to one garden. |
| `panel.py` | Serves `frontend/` under `/plant_garden_static`, registers the panel via `panel_custom` with a content-hash query (`?v=<sha256[:12]>`) for cache busting. |
| `websocket_api.py` | `plant_garden/info` → entry id, garden name, version, admin flag. |
| `runtime.py` | `PlantGardenData` (stored in `entry.runtime_data`) and the typed alias `PlantGardenConfigEntry`. |
| `const.py` | Domain, panel and path constants. |
| `brand/` | `icon.png` (256 px) and `icon@2x.png` (512 px), served by HA's `brands` integration; generated by `scripts/generate_brand.py`. |
| `frontend/` | Built panel bundle (committed, generated by `frontend/`). |

Validation uses `probatio` (HA's replacement for voluptuous since 2026.9).

### Request flow: opening the panel

1. HA loads `plant-garden-panel.js?v=…` from the static path and creates `<plant-garden-panel>` with `hass`, `narrow`, `panel` (`panel.config.entry_id`).
2. The panel calls `plant_garden/info` once and renders the welcome page; later `hass` updates do not trigger new requests.

## Frontend (`frontend/`)

- TypeScript (strict) + Lit 3, built by Vite 8 in library mode into **one ES module** in `custom_components/plant_garden/frontend/`.
- No dependency on HA-internal `ha-*` elements. Icons are inline SVG paths from `@mdi/js`. Styling uses HA theme variables (`src/styles/tokens.ts`); dark mode is mirrored as a `dark` attribute from `hass.themes.darkMode`.
- `src/i18n/` – typed dictionaries (`en.ts` defines the keys, `de.ts` must match); `createLocalize(language)` picks by base language with English fallback.
- `src/api/client.ts` – typed WebSocket calls.
- Tests: Vitest; pure modules in Node, components in happy-dom.

## Development environment

- The Python venv lives in `~/.venvs/ha-plant-garden` (outside the repo, fast on WSL with the repo on a Windows drive). All scripts source `scripts/env.sh`.
- `scripts/develop` starts HA with a config dir in `~/.ha-plant-garden-dev`, symlinking the integration and `dev/*.yaml`. The demo garden (`dev/demo_garden.yaml`) provides `input_boolean` and template-`switch` entities that stand in for irrigation valves.
- `scripts/smoke` runs a throw-away HA and checks onboarding → config flow → panel → WebSocket → bundle.
- `scripts/test-min-version` runs the tests against HA 2026.9.0 in a separate venv.

## CI (`.github/workflows/`)

| Workflow | Jobs |
|---|---|
| `validate.yml` | hassfest, HACS action |
| `python.yml` | version check, ruff, mypy, pytest (pinned HA), pytest (minimum HA) |
| `frontend.yml` | prettier, eslint, tsc, vitest, build, committed bundle up to date |
| `release.yml` | on `v*` tags: runs both test workflows, checks versions against the tag, creates a GitHub release with the CHANGELOG section |
